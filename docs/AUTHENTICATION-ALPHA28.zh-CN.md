# alpha.28 正版验证与断网启动

`0.1.0-alpha.28` 将游戏启动限制为已经 Minecraft 官方服务核验的 Microsoft 账号。设置页面不再提供独立离线身份或第三方验证身份的创建入口，核心 API 同样拒绝创建。这两类历史账号记录保留在本机，但不能用于启动。

联网启动时，核心检查 Minecraft Services 的游戏资格和 Java 玩家资料，要求返回已识别的 Java 资格、有效名称及与当前账号一致的 UUID。游戏进程创建前再次检查当前账号、令牌和核验记录，防止安装或服务器准入期间切换账号后沿用旧结果。平台账号、远程签名和 OPL 隧道均不能代替此检查。

## 已验证账号断网启动

1. 联网完成 Microsoft 授权及官方游戏资格核验，并提前准备游戏文件和 Java 运行时。
2. 打开“设置 → 账号与启动”，将配置作用范围选为“默认游戏设置”，启用“使用已验证账号断网启动”并保存。
3. 为已安装实例选择此前核验过的 Microsoft 账号，再启动游戏。核验记录未过期时使用同一 UUID、名称和 Minecraft 令牌；缺少记录或已过期则要求重新联网核验。
4. 恢复网络后关闭该设置，恢复联网核验和自动更新。

记录保存在既有加密凭据库，绑定账号 UUID、名称、令牌摘要、核验时间和最后使用时间。Windows 下凭据库密钥由 DPAPI 保护。有效期取“Minecraft 令牌到期”和“核验后 24 小时”中较早的时间；断网使用不会续期。仅复制账号列表里的名称或 UUID 不能通过检查。

在线请求发生连接错误时也可使用未过期记录。官方明确拒绝、缺少游戏资格、资料异常、身份不匹配、限流或其他 HTTP/API 错误都会清除核验记录并阻止启动。断网期间无法即时发现资格撤销，客户端也不声称能抵抗控制本机账号或修改程序的攻击者。服务器仍独立决定是否接受连接。

断网设置跳过自动更新，使用已保存并验证签名的远程策略。私有整合包的资格、一次性进服许可等额外条件仍可能要求网络。该功能不允许首次断网验证，也不提供任意离线用户名或令牌为零的替代会话。

## OPL 与升级兼容

OPL 仅传输连接，不颁发账号或游戏资格。旧远程策略中的 `offline-singleplayer`、`offline-opl` 标识保留解析能力，但只表示连接方式，仍须使用通过核验的 Microsoft 账号。仅允许 `offline` 账号的旧策略会被拒绝，需运营者发布允许 Microsoft 账号的新签名策略，客户端不会私自修改远程签名内容。

本次保留应用标识、程序文件名和 `%APPDATA%\MC-Honer` 数据目录，未删除游戏、账号或设置，未自动部署线上服务。旧版本说明保留作为历史记录；其中独立离线身份规则不适用于 alpha.28。

## 验证范围

2026-10-17 在 Windows x64、Node.js 24.19.0 下执行 57 项针对性测试：56 项通过，1 项 PostgreSQL 测试因未配置隔离数据库而跳过。测试使用可控的官方响应，覆盖令牌、资格、缓存到期和绑定、账号切换、远程策略、更新顺序、OPL 与平台资格。进程边界测试实际启动了 Windows 测试程序，验证合法缓存允许创建进程及失效记录阻止创建进程；该程序不是 Minecraft。

安装包采用 Electron 44.7.0，打包启动及中英文界面烟测结果见发布说明。没有完成真实 Microsoft 授权、Minecraft 正版启动、跨网络 OPL 或正版进服验收。目前分发配置未填写已获批准的 AppID，新安装客户端只能浏览和管理实例，不能完成 Microsoft 登录及授权启动。需批准并配置本应用自己的 AppID 后继续真实验收。

完整英文审核说明见 [Authentication and launch controls](AUTHENTICATION-ALPHA28.en.md)。
